# COGNITIVE.md — Когнитивная архитектура ARIA AI-Factory

> **Версия:** 8.0  
> **Дата:** 12 мая 2026  
> **Назначение:** Описание когнитивной архитектуры ARIA: иерархия памяти, Palace Recall, Temporal KG, GraphRAG, эволюция памяти.  
> **Принцип:** ARIA не просто хранит данные — она их организует, связывает, эволюционирует и контролируемо забывает.

---

## 1. ИЕРАРХИЯ ПАМЯТИ (L0–L3 + WARM + EPISODIC + COLD)

| Уровень | Название | Содержание | TTL | Загрузка |
|---------|----------|------------|-----|----------|
| **L0** | Identity | `SELF_REFERAT.md`, `RULES.md`, `AGENTS.md` | ∞ | Всегда |
| **L1** | Facts | `TASKS.md`, `CONSTITUTION.md`, `SKILLS.md` | ∞ | Всегда |
| **L2** | Context | Контекст текущей задачи, активные гипотезы | Сессия | По требованию |
| **L3** | Deep | `Temporal KG`, `MemPalace`, `GraphRAG` | ∞ (с `valid_to`) | Поиск |
| **HOT** | Working | Последние 10 событий, текущие ордера, алерты | 24 часа | Всегда (лимит 10) |
| **WARM** | Decisions | Архитектурные решения, подтверждённые стратегии | 14 дней | По запросу |
| **EPISODIC** | Episodes | Цепочки «причина → действие → исход» для Memory Evolution | 90 дней | Поиск / Replay |
| **COLD** | Archive | Старые логи, устаревшие стратегии, аудиторские следы | ∞ | Архив |

## 2. СТРУКТУРИРОВАННАЯ ПАМЯТЬ (MemPalace)

Иерархический дворец памяти, основанный на методе локусов (loci).

- **Wings** — проекты / рынки (Bybit, Hyperliquid, Arbitrage, MEV)
- **Halls** — типы памяти (facts, events, discoveries, preferences, advice, strategies)
- **Rooms** — темы (rate_limits, stop_loss, order_validation, mev_patterns, data_quality)
- **Closets** — суммаризация (сжатые представления для быстрого поиска)
- **Drawers** — оригинальные файлы (сырые логи, транзакции, снапшоты)

**Поиск:** фильтрация по Wing+Room даёт recall до **94.8%** (против 60.9% без структуры).

---

## 3. ВРЕМЕННОЙ ГРАФ ЗНАНИЙ (Temporal KG)

Каждый факт имеет обязательные поля:
- `subject` — субъект (адрес, агент, контракт)
- `predicate` — предикат (тип связи: `executed`, `attacked`, `profiled`)
- `object` — объект (транзакция, стратегия, паттерн)
- `valid_from` — начало действия факта
- `valid_to` — окончание действия (если `valid_to < now` → факт **автоматически удаляется**)
- `confidence` — уверенность (0.0 – 1.0)

**Запросы** к графу автоматически исключают устаревшие факты (`valid_to < now`).

---

## 4. СЕМАНТИЧЕСКИЙ ГРАФ (GraphRAG)

Дополнительный слой поверх Temporal KG:
- **Автоматическое извлечение сущностей** из отчётов `probe-mcp`, `analytics-mcp`, `crustdata-scout`.
- **Построение семантических связей** между разрозненными фактами (бот X связан с пулом Y, который использует арбитражер Z).
- **Кластеризация** (алгоритм Лейдена) для выявления групп связанных целей.
- **Суммаризация** — авто-генерация «досье» на кластеры (community reports).

---

## 5. ЭВОЛЮЦИЯ ПАМЯТИ (Memory Evolution)

Непрерывный фоновый процесс, управляемый `judge-mcp`:

| Фаза | Описание |
|------|----------|
| **Добавление** | LLM извлекает сущности и связи из новых данных, сохраняет в Temporal KG + векторную БД. |
| **Связывание** | Автоматическое построение связей с историческими фактами (GraphRAG). |
| **Ревизия** | Фоновый процесс пересматривает старые записи, обновляет описания и связи. |
| **Забывание** | TTL-кластеризация: факты с истекшим `valid_to` или низким `confidence` удаляются (Controlled Forgetting). |
| **Сжатие** | WARM Memory: дубликаты склеиваются, старые версии заменяются новыми. |

## 6. PALACE RECALL (Метод локусов)

При сохранении инцидента агент указывает `wing`, `hall`, `room`.  
При поиске — возможность фильтрации по иерархии для максимального recall.

**Формат запроса:**

@memory: recall --wing=MEV --hall=events --room=sandwich_attacks

## 7. ИНСТРУМЕНТЫ РАБОТЫ С ПАМЯТЬЮ (MCP)

| Инструмент | Назначение |
|------------|------------|
| `memory-mcp` | Основное хранилище: SPO-триплеты, векторы, графы. |
| `mem0-mcp` | Гибридная память: векторы + граф с LLM-экстракцией сущностей. |
| `mem-palace-mcp` | 19 инструментов поиска, навигации, графов (Wings, Halls, Rooms). |
| `a-mem-mcp` | Эволюция памяти: ревизия, перелинковка, забывание. |
| `notebooklm-mcp` | Zero-token research: конвейер знаний из PDF, Markdown. |
| `auto-memory-audit` | Ежедневный аудит: дедупликация, удаление устаревших фактов. |
| `context-compress` | Авто-сжатие контекста при превышении 70% окна. |
| `self-describing-data` | Семантическая аннотация каждого факта при сохранении. |
