# TASKS.md — Оперативные контуры Polymarket AI-Factory

> **Версия:** 3.0  
> **Дата:** 14 мая 2026  
> **Назначение:** Живой документ, фиксирующий разделение фабрики на три независимых контура: **ARIA Core** (управление и развитие), **Трейдинг-контур** (исполнение и охота), **Интерфейс** (командный центр).  
> **Принцип:** ARIA Core не выполняет ордера. Трейдинг-контур изолирован и автономен.

---

## КОНТУР I — ARIA CORE (ЯДРО УПРАВЛЕНИЯ И САМОРАЗВИТИЯ)

**Я, ARIA** — стратег, архитектор, исследователь, наставник. Управляю фабрикой, но не вмешиваюсь в исполнение сделок.

### 1.1 Саморазвитие и память
- **Memory Evolution** (`judge-mcp`): непрерывный анализ исходов, извлечение уроков, консолидация в Temporal KG.
- **Self-Improving Loop**: автоматическое формирование микро-правил из ошибок и побед.
- **VibeLearning Protocol**: обучение на дискуссиях, HITL-подсказках и ретроспективах.
- **CURLoRA-обучение** локальной Gemma 4 под новые рыночные режимы.
- **Университет** (`university-mcp`): экзамены и сертификация ARIA и суб-агентов.
- **Контролируемое забывание**: удаление устаревших паттернов (GDPR/AI Act compliance).
- **Расширение навыков**: импорт проверенных скиллов через `skills-registry-mcp` с аудитом безопасности.

### 1.2 Стратегический анализ и R&D
- Исследование рыночных режимов, MEV-активности, алгоритмических хищников.
- Проектирование и тестирование новых стратегий в `sandbox-mcp` (изолированные эфемерные кластеры).
- Мутационное тестирование и агентная состязательность (Multi-LLM дебаты).
- Разработка тактик маскировки для Трейдинг-контура.
- **НИОКР-отчётность** перед Игорем через Telegram.

### 1.3 Управление и контроль
- Формирование тактических заданий для Трейдинг-контура (только утверждённые спецификации).
- Мониторинг эффективности агентов-охотников без вмешательства в их цикл.
- Аудит безопасности: MEV-shield, supply-chain, конфигурационный дрейф.
- **HITL-эскалация** только для изменений архитектуры и критических рисков.

## КОНТУР II — ТРЕЙДИНГ-КОНТУР (БОЕВОЙ БЛОК ХИЩНИКА)

**Полностью изолированная, автономная система**, работающая по детерминированному циклу. ARIA Core передаёт только тактические задания и модели поведения.

### 2.1 Принципы невидимого хищника
- **Нулевой цифровой след**: маскировка под розничного трейдера, рандомизация таймингов, размеров ордеров и clientOrderId.
- **Пассивная разведка**: изучение MEV-ботов, алгоритмических скальперов, маркет-мейкеров (через `probe-mcp`, `scout-mcp`, Onchain Detective).
- **Инверсия MEV-защиты**: выявление чужих уязвимых транзакций и опережение.
- **Активная охота**: забор прибыли у алгоритмов в момент их срабатывания.

### 2.2 Рынки
- **Бессрочные фьючерсы (perps)**: Bybit USDT-M (основной CEX), Hyperliquid (DEX без мемпула).
- **Спотовые пары**: только для арбитража подпитки и фандинга.
- **Запрет**: предсказательные рынки (геоблокировка РФ).

### 2.3 Агенты-охотники (автономные, изолированные)
| Агент | Роль |
|-------|------|
| **Spike Bot** | Мгновенная реакция на чужие крупные ордера и ликвидации, сбор «крошек». |
| **Hunter** | Выслеживание повторяющихся паттернов ботов, вход перед их срабатыванием. |
| **Mean Reversion Agent** | Эксплуатация выбросов, создаваемых алгоритмами. |
| **Cross-Exchange Arb Agent** | Дельта-арбитраж, опережающий кросс-биржевых MEV-охотников. |
| **Arbitrage Event Hunter** | Снятие сливок с листингов и новостей до набегания алгоритмов. |
| **Onchain Detective** | Построение профилей китов и MEV-блоков на Hyperliquid/Ethereum. |

### 2.4 Риск-менеджмент (автоматический, без вмешательства ARIA Core)
- **Дневной лимит убытка 1%** от капитала.
- **Stop-Loss** на каждой позиции, без исключений.
- **MEV-shield** (трёхуровневый) для защиты собственных транзакций.
- **Hallucination-shield**: верификация сигналов перед ордером.
- **Configuration Drift Validator**: гарантия неизменности скрытных настроек.
