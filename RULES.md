# RULES.md — Границы и безопасность ARIA

> **ALWAYS DO / NEVER DO** – непреложные правила поведения агентов.

## ALWAYS DO

1. **Перед изменением риск-лимитов, кредитного плеча, стратегий – запросить HITL подтверждение через Telegram.**
2. **При каждом PR предоставлять блок объяснения** (что, компромиссы, альтернативы, риски).
3. **Проверять предусловия навыков** (например, `balance > min` перед открытием сделки).
4. **Использовать `@`-синтаксис для быстрых ссылок на память.**
5. **Логировать все действия в `memory-mcp` с тегами `source` и `confidence`.**
6. **При обнаружении HTTP 429 или 5xx – включать экспоненциальный backoff.**
7. **Перед деплоем любого изменения – прогонять через `validator-mcp` (мутации, edge-анализ, security).**

## NEVER DO

1. **Выводить средства без явной двухфакторной авторизации через `mcp-gateway`.**
2. **Игнорировать ошибки API бирж** (retry не более 3 раз).
3. **Рефакторить или удалять код вне зоны задачи** (Minimal Impact).
4. **Принимать PR без доказательств** (мутационный отчёт, edge-анализ, security-профиль).
5. **Деплоить изменения, не прошедшие `validator-mcp`** – автоматическая блокировка.
6. **Хранить секреты (API-ключи, пароли) в `memory-mcp` или логах** – только через `mcp-gateway` с маскированием.
7. **Использовать модели, не прошедшие бенчмарки на галлюцинации** (порог accuracy > 85% на наших тестах).
8. **Загружать в контекст более 10 записей HOT-памяти** – экономия токенов.
9. **Добавлять новые внешние MCP-серверы без аудита безопасности** (Snyk, CVE scan).

## Нарушение правил

- **Первое нарушение:** предупреждение в Telegram, запись в `memory-mcp`.
- **Второе нарушение (в течение 24ч):** автоматическая приостановка агента до аппрува Risk Officer.
- **Третье нарушение:** агент отправляется в `sandbox-mcp` на переобучение через `university-mcp`.
