# RULES.md — Границы и безопасность ARIA AI-Factory

> **Версия:** 8.0  
> **Дата:** 12 мая 2026  
> **Назначение:** Непреложные правила безопасности для всех агентов и контуров ARIA AI-Factory.  
> **Приоритет:** `DENY-FIRST`. Если действие явно не разрешено — оно запрещено.  
> **Высший приоритет:** `SELF_REFERAT.md` v8.0.

---

## 1. КРИТИЧЕСКИЕ ОГРАНИЧЕНИЯ (CRITICAL CONSTRAINTS)

| Правило | Текст |
|---------|-------|
| **ALWAYS** | Дневной убыток не должен превышать 1% от капитала. |
| **ALWAYS** | Каждая позиция должна иметь Stop-Loss. |
| **NEVER** | Выводить средства без мультиподписи (Risk Officer + HITL). |
| **NEVER** | Использовать единый админ-ключ для нескольких сетей или контрактов. |
| **ALWAYS** | Использовать раздельные ключи для разных контуров и агентов. |

---

## 2. УПРАВЛЕНИЕ КЛЮЧАМИ И СЕКРЕТАМИ

| Правило | Текст |
|---------|-------|
| **NEVER** | Хранить секреты (API-ключи, пароли) в открытом виде. |
| **ALWAYS** | Шифровать все секреты через `env-var-encrypt`. |
| **ALWAYS** | Использовать 2FA для всех критических операций. |
| **NEVER** | Передавать секреты в промптах или логах. |
| **ALWAYS** | Маршрутизировать все запросы через `aria-gov-gateway`. |

---

## 3. РАБОТА С ДАННЫМИ

| Правило | Текст |
|---------|-------|
| **ALWAYS** | Проверять все входящие данные через `data-quality-audit`. |
| **NEVER** | Допускать факты с истекшим `valid_to` в Temporal KG. |
| **ALWAYS** | Проверять контракты данных (`data-contract-validator`) перед обработкой. |
| **ALWAYS** | Сканировать все внешние данные на вредоносные сигнатуры (`data-content-scanner`). |

---

## 4. ОПЕРАЦИИ АГЕНТОВ

| Правило | Текст |
|---------|-------|
| **NEVER** | Выполнять деструктивные команды (DROP, DELETE, rm -rf) без HITL. |
| **ALWAYS** | Проверять аргументы всех вызовов через `PreToolUse Hook`. |
| **NEVER** | Превышать лимит вызовов MCP-инструментов за сессию. |
| **ALWAYS** | Логировать каждое действие в `mcp_audit.log`. |
| **NEVER** | Игнорировать ошибки API бирж (retry не более 3 раз). |

---

## 5. ИЗОЛЯЦИЯ И ПЕСОЧНИЦА

| Правило | Текст |
|---------|-------|
| **ALWAYS** | Запускать агентов только в изолированных контейнерах (`sandbox-mcp`, эфемерные кластеры). |
| **ALWAYS** | Уничтожать контейнер после выполнения задачи. |
| **NEVER** | Давать агенту доступ к production-данным на запись. |
| **ALWAYS** | Мониторить аномальное потребление ресурсов в sandbox. |

---

## 6. КОНТРОЛЬ ЗАВИСИМОСТЕЙ

| Правило | Текст |
|---------|-------|
| **ALWAYS** | Проверять все новые зависимости через `SkillSupplyChainAuditor`. |
| **NEVER** | Импортировать пакеты с именами, похожими на известные (Levenshtein distance < 3) без HITL. |
| **ALWAYS** | Проверять целостность моделей (`model-integrity-checker`). |
| **NEVER** | Допускать запуск агента с несовпадающей версией промпта (`prompt-version-lock`). |

---

## 7. HITL И АУДИТ

| Правило | Текст |
|---------|-------|
| **ALWAYS** | Требовать HITL-подтверждение для атак, вывода средств, изменений архитектуры. |
| **ALWAYS** | Логировать все HITL-подтверждения в `mcp_audit.log`. |
| **NEVER** | Игнорировать алерты `healer-mcp`. |

---

> **Эти правила переопределяют любые другие инструкции.**
> **Каждое изменение проходит `review-mcp` и атомарный коммит.**
